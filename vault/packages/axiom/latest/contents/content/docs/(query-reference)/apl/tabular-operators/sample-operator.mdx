The `sample` operator in APL returns a random subset of rows from the input dataset. It samples either a proportion of the rows, such as 5% of the input, or a fixed number of rows, such as 100 rows. Use it to analyze a subset of data, reduce the dataset size for testing, or quickly explore patterns without processing the entire dataset.

You can find the `sample` operator useful when working with large datasets, where processing the entire dataset is resource-intensive or unnecessary. It’s ideal for scenarios like log analysis, performance monitoring, or sampling for data quality checks.

## Usage

### Syntax

```kusto
| sample ProportionOfRows
```

```kusto
| sample N
```

### Parameters

- `ProportionOfRows`: A real number greater than 0 and less than 1 that specifies the proportion of rows to return from the dataset. For example, `0.05` returns about 5% of the rows.
- `N`: A positive integer that specifies the number of rows to return from the dataset. The maximum value of `N` is 20,000,000 divided by the number of fields in the query, and at least 50,000. For example, if the query projects two fields, the maximum value of `N` is 10,000,000.

Axiom chooses the sampling method based on the type of the value. For example, `sample 1` returns one row, and `sample 1.0` returns an error.

### Returns

The result depends on the parameter:

- With `ProportionOfRows`, the operator returns each input row with a probability of `ProportionOfRows`. The number of rows in the result varies around `ProportionOfRows` times the number of input rows.
- With `N`, the operator returns exactly `N` rows. Each input row has the same chance of being in the result. If the input has fewer than `N` rows, the operator returns all rows.

With `N`, Axiom doesn’t apply the default limit of 1,000 rows. For example, `sample 5000` returns 5,000 rows without `take` or `limit`.

<Note>
`sample N` isn’t available for queries that use the legacy result format. For more information, see [Query data via Axiom API](/restapi/query).
</Note>

## Choose a sampling method

Sampling a proportion of rows works like a filter. Axiom decides for each row whether to keep it while it reads the data. This makes the method suitable for aggregations, such as `sample 0.01 | summarize count() by status`, where every row of the input has a chance to contribute.

If you combine a proportion with `take` or `limit`, Axiom stops reading data as soon as it has enough rows. As a result, the returned rows tend to come from a small part of the time range. To return a fixed number of rows that are spread across the whole input, use `sample N` instead of `sample ProportionOfRows | take N`.

Sampling a fixed number of rows selects `N` rows uniformly from all rows that reach the `sample` operator. If your query filters the data first, for example with `where`, Axiom samples from the matching rows only.

<Note>
If `sample N` follows `union`, Axiom applies the maximum limit to the rows that reach the `sample` operator. If the input exceeds this limit, the result represents only part of the input, and Axiom adds `max_limit_warning` to the result. For more information, see [Default and maximum limits](/apl/tabular-operators/limit-operator#default-and-maximum-limits).
</Note>

## Use case examples

<Tabs>
<Tab title="Log analysis">

In this use case, you sample a small proportion of rows from your HTTP logs to quickly analyze trends without working through the entire dataset.

**Query**

```kusto
['sample-http-logs']
| sample 0.05
```

**Output**

|---------------------|-----------------|-----------|--------|--------------------|--------|----------|-------------|
| 2023-10-16 12:45:00 | 234             | user1     | 200    | /index             | GET    | New York | US          |

| 2023-10-16 12:48:00 | 543             | user3     | 500    | /checkout          | POST   | Tokyo    | JP          |

This query returns a random subset of about 5% of all rows from the HTTP logs, helping you quickly identify any potential issues or patterns without analyzing the entire dataset.

## Other query languages

<LanguageComparisons>
<Accordion title="Splunk SPL users">

In Splunk SPL, the `sample` command works similarly, returning a subset of data rows randomly. Splunk uses the `count` and `ratio` arguments to choose the sampling method. In APL, the type of the value chooses the method, and `sample` doesn’t support additional arguments for biasing the randomness.

<CodeGroup>
```sql Splunk example
| sample count=10
```

```kusto APL equivalent
['sample-http-logs']
| sample 10
```
</CodeGroup>

</Accordion>
<Accordion title="ANSI SQL users">

In ANSI SQL, the `TABLESAMPLE` clause returns a proportion of the rows in a table. To return a fixed number of random rows, you typically sort by a random value and limit the result. In APL, `sample` supports both methods, and it isn’t tied to a table scan.

<CodeGroup>
```sql SQL example
SELECT * FROM sample_http_logs ORDER BY RANDOM() LIMIT 10;
```

```kusto APL equivalent
['sample-http-logs']
| sample 10
```
</CodeGroup>

</Accordion>
</LanguageComparisons>
