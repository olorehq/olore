Your [account role](/admin/team-management/overview#team-member-roles) grants permissions for actions on resources. Each permission has an ID in the form `resource:action`: for example, `checks:run` is **Run checks**.

The tables below list all account permissions, using the names, descriptions, groups, and resource rows from the role editor. Use your browser's search to find an ID or name. A permission does not enable a feature your account or plan does not include.

## Find or request access

Ask your account owner or an admin to [assign a role](/admin/team-management/managing-team-members#change-members’-roles) with the permissions you need. See the [built-in role comparison](/admin/team-management/overview#team-member-roles) to choose a suitable role.

If [custom roles](/admin/team-management/custom-roles) (beta) are enabled for your account, you can find permission names under **Account settings > Roles**. The editor shows names rather than IDs; the headings below match its groups and resource rows. Someone who can edit roles can adjust permissions within the [limits on granting access](/admin/team-management/custom-roles#the-permission-matrix).

<Note>
Custom roles are in beta and are not generally available. The Roles page appears only on accounts where they are enabled.
</Note>

Every role includes `account:read`, `members:read`, and `maintenance-windows:read`; these have no checkbox. Only the Owner can hold `account:delete` and `account:transfer-ownership`. Other permissions may require additional permissions, which the [custom-role editor](/admin/team-management/custom-roles#the-permission-matrix) selects together.

The role editor hides the legacy API-key permission `api-keys:read-locked` and shows **Snippets** permissions only when your account already has snippets. They remain listed here for reference.

Account permissions are separate from [MCP session permissions](/ai/mcp-server/security-and-permissions#role-checks). An MCP session must allow a tool, and your account role must allow its action.

## Monitoring

| Permission ID | Name in the role editor | Description |
| --- | --- | --- |
| `checks:read` | View checks | View checks and monitors (incl. heartbeats) with their results, status, stats, events, alert history, traces, metrics and analytics. |

| `checks:create` | Create checks | Create checks and monitors, including cloning one and setting up checks in a connected GitHub repository. |

| `checks:delete` | Delete checks | Delete checks and monitors. |
| `checks:run` | Run checks | Run checks on demand: ad-hoc runs from the editor, Schedule now and triggered check sessions. |
| `checks:cancel` | Cancel check runs | Cancel a running check session. |
