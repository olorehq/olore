## Full release history

<Update label="v8.13.0" tags={["November 2026"]}>
- Added opt-in [check-level Prometheus metrics](/platform/private-locations/agent-metrics#check-level-metrics). Set `AGENT_METRICS_PER_CHECK=true` to get result counts, status and timing metrics per check, modelled on the Prometheus V2 integration.
- `LOG_LEVEL` now applies to the Go process that runs API checks and uptime monitors. Before, it only applied to the synthetics worker.
- Security: the bundled Chromium and Chrome now reject TLS chains through the eight compromised eMudhra intermediate CAs and their Sectigo cross-signs.
</Update>

<Update label="v8.12.0" tags={["October 2026"]}>
- Security: updated every bundled Node.js to releases that fix CVE-2026-111497 (Brotli remote code execution) and carry the current CA store. Runtime 2026-04 now runs Node.js 24.22.1 (was 24.13.1), and Playwright Check Suites run on Node.js 22.23.4, 24.22.1 or 26.12.1. Upgrade to this version or newer.
- Added Bun 1.4 as a Playwright Check Suite engine version.
- Improved secret scrubbing for Browser and Multistep checks. Secrets are now removed from traces, reports and logs before upload, including request and response bodies, attachments and encoded values.
- Secrets are now also removed from API check setup and teardown script logs.
- A trace that cannot be fully scrubbed is left out of the result, and the check log says why.
- Playwright Check Suites scrub secrets several times faster.
- The agent now exposes a single port, 8080, for health probes and Prometheus metrics. If your Kubernetes probes or scrape configuration use port 8081 or 8082, point them to 8080.
- A single `/metrics` endpoint now covers every check type the agent runs. Use the `component` label to separate uptime metrics from synthetics metrics. Metric names and labels are consistent across both, so one dashboard covers the whole agent.
- Added the `CHECKLY_RUN_FILE_MAX_BYTES` environment variable to cap the size of files the agent reads from a Browser or Multistep check run, such as the Playwright report. A file above the cap is left out of the check result. The default is just under 2 GiB. See [agent configuration](/platform/private-locations/agent-configuration).
</Update>

- Added compression for logs and reports from scheduled checks, enabled per account, to reduce artifact upload sizes.
- Updated agent and bundled 2026-04 runtime dependencies to fix vulnerabilities.
</Update>

<Update label="v7.0.0" tags={["March 2026"]}>
  - Added support for running [ICMP](/detect/uptime-monitoring/icmp-monitors/overview) and [DNS monitors](/detect/uptime-monitoring/dns-monitors/overview) on private locations
  - Introduced the [uptime agent image](/platform/private-locations/agent-images#uptime-image), a lightweight version of the agent for running uptime monitors (URL, DNS, TCP, ICMP) only
  - Added [external observability](/platform/private-locations/agent-configuration#external-observability) for private location agents to capture runtime errors
    - Error-level events can be reported to Checkly to help detect crashes, bugs, and environment-related issues
    - Only limited technical metadata is collected (error message, stack trace, agent version, platform, Go runtime)
    - Sensitive data such as API keys, environment variables, check configuration, URLs, headers, and response bodies is never sent
    - Enabled by default, can be disabled with `EXTERNAL_OBSERVABILITY=off`
  - Support for runtimes `2026.04` and `2025.04`

  **Breaking changes**

  - API checks and URL monitors migrated to the Go runner now percent-encode reserved characters in query parameter data, following [RFC 3986, Section 2.2](https://datatracker.ietf.org/doc/html/rfc3986#section-2.2). For example, `(` and `)` are sent as `%28` and `%29`. Target servers that treat the encoded and unencoded forms differently may require changes.
  - TLS certificate validation for an IP-address target now requires the certificate to contain that IP address in its Subject Alternative Name as an `iPAddress`, following [RFC 5280, Section 4.2.1.6](https://datatracker.ietf.org/doc/html/rfc5280#section-4.2.1.6). Checks targeting an IP address fail TLS validation when the certificate does not contain a matching IP address SAN.
</Update>
