To kickstart a new project with the CLI, we recommend running `npx checkly init`. But you can also add the CLI
from scratch with the following steps.

## Prerequisites

- Node.js `22.13+`.
- A text editor like [Visual Studio Code](https://code.visualstudio.com/).

## Installation

First, install the CLI.

```bash Terminal
npm i --save-dev checkly
```

Create a minimal `checkly.config.ts` (or `checkly.config.js`) at the root of your project. We recommend using TypeScript.

Use the CLI to [authenticate](/cli/authentication) and pick a Checkly account. Make sure you have [signed up for a free account on checklyhq.com](https://www.checklyhq.com/)
before hand or just sign up for a new account straight from the terminal.

```bash Terminal
npx checkly login
```

## Global installs and `npx checkly@<version>`

Run the CLI through `npx checkly` from your project (or your package manager's equivalent, such as `pnpm exec checkly` or `yarn checkly`), so the CLI version is the one in your `package.json`.

Your checks only load with the `checkly` package your project installs, because they register with that copy. Since CLI version 10.0.0, when you run `checkly` from any other installation, for example a global `npm i -g checkly`, `pnpm dlx checkly` or `npx checkly@<version>`, inside a project that has its own `checkly` package, the CLI hands the command to your project's installation, as `npx checkly` or its equivalent would. This applies to every command. The CLI looks for your project's installation from the directory of the `--config` file if you pass one, and from the current directory otherwise. If the two versions differ, the CLI says which version runs. To use another version, install that version in your project.

Set `CHECKLY_NO_DELEGATION=1` to turn off the hand-off. Older global installs, and any install with the hand-off turned off, fail on projects that have their own `checkly` package with `Unable to create a construct ... outside a Checkly CLI project`.

## Using a Proxy Server

The CLI respects the common proxy environment variables for any outbound traffic, like running `npx checkly test`
or `npx checkly deploy`. Because the CLI connects over HTTPS, set `HTTPS_PROXY` (or `ALL_PROXY`). `HTTP_PROXY` alone isn't used for these connections. Use `NO_PROXY` to bypass the proxy for specific hosts.

```bash Terminal
HTTPS_PROXY=https://proxy-url npx checkly test
```

The CLI communicates with the following domains if you need to allow-list them in your proxy:
- `api.checklyhq.com`
- `events.checklyhq.com`
